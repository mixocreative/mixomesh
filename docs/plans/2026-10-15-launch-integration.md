# Launch integration — call MIXOMESH from another app (Windows desktop) · plan (2026-10-15)

Ledger on execution: `docs/handoff/launch-integration.md` (create at LI.0, update every task). Design authority: ADR 0001 (+ addendum from LI.9), Blueprint §11 "Electron security".

## Goal

`MIXOMESH.exe --open <file> [--open <file>…] [--library <folder>]` and bare `MIXOMESH.exe <file.mixo>` (double-click): a `.mixo` opens as the project (dirty-confirm first), GLB/glTF/3MF/OBJ/STL are imported into the scene through the drag-and-drop import path, `--library` mounts the folder in the Library tab exactly like the Mount button and persists it as the last mount. A second launch forwards to the running window. Installer registers `App Paths` + an install-location key so other apps find the exe. Desktop only. Not in scope: `mixomesh://`, `--export`/report-back, macOS.

## Binding decisions

- **D1 Paths stay in main.** Argv → `electron/LaunchArgs.cjs` (pure parse + validate, injectable fs) → existing opaque tokens (`_fileRefs.registerFile` writable for `.mixo`, read-only for imports; `registerMount` for the folder). Renderer gets `{kind, ref, name}` + error strings carrying **basenames only**, over one IPC pair: `launch:pull` (renderer, via trusted `handle`) and `launch:requests` (main → renderer). No new path-taking IPC channel.
- **D2 Validation (fail closed, each arg independently):** resolve against the launching cwd (`process.cwd()` first instance, `workingDirectory` from `second-instance`); reject `\\?\`, `\\.\`, UNC device syntax, reserved device names, any `:` after the drive letter (ADS), NUL; `fs.realpath` (resolves symlinks/junctions/`..`) then `stat`: regular file for opens, directory for library; extension allowlist `mixo glb gltf 3mf obj stl` (case-insensitive); size ≤ `MAX_WRITE_BYTES` (1 GiB, reuse constant); ≤ 32 opens per launch; one `--library` (last wins). Bad args never block startup: they become `errors[]` in the batch → one toast listing basenames + reasons.
- **D3 Argv parsing** (`parseLaunchArgv(argv, {isPackaged})`): strip the leading exe (+ `main.cjs` when unpackaged); accept `--open <v>`, `--open=<v>`, `--library <v>`, `--library=<v>`, and positionals whose extension is on the allowlist (file association = bare `.mixo`). Every other `-`-prefixed token (Electron/Chromium switches: `--inspect`, `--remote-debugging-port=`, `--no-sandbox`, `--user-data-dir=`…) is ignored, and a positional directly after an unknown flag is accepted only by the extension rule. `--` ends flag parsing. `MIXO_SMOKE=1|save` behaviour untouched (no args → empty batch → nothing happens).
- **D4 Single instance:** `app.requestSingleInstanceLock()` before `whenReady`; loser exits 0 immediately (after `app.quit()`). `second-instance` → parse+validate → enqueue → restore/focus window. Smoke/dev runs (`!app.isPackaged`) take the lock too but with a userData-scoped lock (Electron ties the lock to userData, so `MIXO_SMOKE=save`'s temp userData never collides).
- **D5 Queue / no race:** main keeps `_launchQueue` per window. Renderer marks itself ready by invoking `launch:pull` AFTER `bootstrap()` finishes (after `BootBanner.runBootChecks()` is kicked off, same tick); the reply is the queued batch and flips `_launchReady`. Later batches are `webContents.send('launch:requests', batch)`. `did-start-loading` (reload) resets `_launchReady=false` so a reloading renderer never loses a batch.
- **D6 Renderer order per batch** (`src/core/LaunchRequests.js`, serial, each step under `safeAsync`/`safeImport`): (1) `.mixo` (last one if several; others reported as skipped) → `storage.readFile(ref)` → `PersistenceManager.openPicked({ref, file})` (dirty-confirm; `cancel` skips the open but still does 2–3); (2) `--library` → `AssetPanel.mountFromRef({ref,name})` (= `DirMounts.registerMount` + `_mountRef` + `LAST_MOUNT_KEY`, identical to the Mount button; if the folder is already mounted, just select it); (3) imports → `ViewportDrop.importPicked(picked)` (extracted from `promptImport`, same sibling/MTL grouping, stagger, `safeImport`). `assertNoImportInFlight` already guards (1); if an import is in flight, the batch waits for `PROJECT_LOADED`/import completion (poll ≤ 30 s) then runs.
- **D7 Installer:** `nsis.include: electron/installer.nsh` (buildResources is `electron/`, so this is also the default lookup) with `customInstall` / `customUnInstall` macros writing/deleting under `SHELL_CONTEXT` (= HKCU because `perMachine: false`): `Software\Microsoft\Windows\CurrentVersion\App Paths\${APP_EXECUTABLE_FILENAME}` (default = `$INSTDIR\${APP_EXECUTABLE_FILENAME}`, `Path` = `$INSTDIR`) and `Software\MIXOMESH` (`InstallLocation` = `$INSTDIR`, `Version` = `${VERSION}`). `.mixo` association via declarative `win.fileAssociations: [{ext: mixo, name: MIXOMESH project, description, role: Editor}]` (electron-builder emits `Software\Classes\.mixo` + `shell\open\command "$appExe" "%1"` and removes it on uninstall). Verified in `node_modules/app-builder-lib` 26.15.3 templates (`installSection.nsh` `!ifmacrodef customInstall`, `uninstaller.nsh` `customUnInstall`, `include/FileAssociation.nsh`).
- **D8 Keep contracts:** no `.mixo` schema change; `mixo-kv.json` must still contain no OS path (save smoke asserts it); `ipcMain.handle` stays wrapped once (security test counts it); new `ipcMain.on` listeners check `isTrustedSender` (test counts those too).

## Risks

- **Second-instance argv quoting/cwd:** Windows passes raw argv; paths with spaces arrive intact, relative paths must use `workingDirectory`. Covered by LI.1 tests + LI.6 second-instance step.
- **Electron single-instance + smoke runs:** lock is per userData; `MIXO_SMOKE=1` uses the real dev userData → a running `npm run electron` would make the smoke exit 0 as "forwarded". Mitigation: smoke modes always use temp userData (extend `_smokeDir` to all smoke modes in LI.6) — behaviour of the security/save probes is unchanged.
- **Renderer reload mid-batch:** D5 reset handles it; a batch already delivered but not finished is lost on reload (acceptable, same as a manual drop).
- **File association on dev machines:** `fileAssociations` is installer-only; `npm run electron` never registers anything.
- **NSIS warnings as errors:** keep `installer.nsh` to `WriteRegStr`/`DeleteRegKey` with `SHELL_CONTEXT` only; test with `npm run dist` before commit (LI.5 acceptance).
- **Haiku docs invent facts** (PB.10): main proofreads LI.8/LI.9 against grep.

## Owner decisions (recommendation first; used as default until overridden)

1. **Second launch while the project is dirty and a `.mixo` is passed:** recommend the normal dirty-confirm dialog (Save / Discard / Cancel); Cancel skips only the open, imports and library still apply.
2. **`--library` when other folders are already mounted:** recommend ADD + select (never unmount the user's folders); it becomes the last-mount offer on next boot, like the Mount button.
3. **Installer registry check:** recommend the opt-in `scripts/installer-smoke.mjs` (LI.7) run by the owner once per release, not CI (touches HKCU, needs the built installer); manual `reg query` steps documented as fallback.
4. **Positional non-`.mixo` files** (e.g. `MIXOMESH.exe part.glb`): recommend treating them as `--open` (harmless, convenient); only `.mixo` gets a file association.
5. **Limits:** 32 files per launch, 1 GiB per file (reuses `MAX_WRITE_BYTES`). Raise if the owner's caller batches more.
