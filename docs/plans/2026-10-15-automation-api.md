## 2. Transports — comparison and recommendation

| Transport | Who can call / auth | Pros | Cons | Verdict |
|---|---|---|---|---|
| **CLI flags one-shot** (`--open … --library …`, LI) | anyone who can run the exe (same user) | zero protocol, works from any language, already built | fire-and-forget: no results back (second instance exits 0 at once) | KEEP (shipped). Only `--job/--result` added. |
| **Batch job** `MIXOMESH.exe --job job.json --result out.json [--hidden] [--quit]` | same user | one-shot convert pipeline, exit code, no socket client needed; same window renders PNG/thumbnail (RTT, not screen) | needs the real app (GPU) — no Node-only pipeline (export/render seams are renderer code by design); long jobs | **BUILD NOW** (v1). With a running instance: the job is forwarded to it over the pipe and the result still lands in `--result` (the second process acts as a client). |
| **Local IPC — Windows named pipe, JSON-RPC 2.0, NDJSON** `\\.\pipe\mixomesh-<user-sid-hash>` | same interactive user: pipe is created by the user's process; plus a 32-byte random **session token** in `<userData>/api/session.json` (ACL = user profile) that every connection must present in `hello` | live session, results + events, no port, no DNS-rebinding/CSRF class, works from Python/C#/Node/PowerShell (`\\.\pipe\…` is a file handle) | Windows-only (macOS deferred anyway); Node cannot set a pipe DACL → token file is the ACL | **BUILD NOW** (v1) |
| localhost HTTP/WebSocket | any local process **and any web page** (DNS rebinding, CSRF) unless token + Host/Origin checks | universal clients | opens a browser-reachable surface for a hobbyist app; must bind 127.0.0.1, token, Origin deny-all, port file | **REJECT for v1**; opt-in bridge over the pipe in v2 only if a caller cannot open a pipe (NEEDS OWNER DECISION) |
| stdin/stdout JSON (child process) | the parent process only | simplest for a Blender add-on / Python `subprocess` | Electron re-spawn per use (slow boot), conflicts with single-instance lock | **v2 thin client**: `MIXOMESH.exe --rpc` = stdio⇄pipe relay (no second server) |
| Hot folder (file drop) | anyone with write access to the folder | no code on caller side | polling, no results, ambiguous ordering | LATER / never |
| Web `postMessage` embed | host page on an allowlisted origin | the only web-build option | origin allowlist, blob-only I/O, no paths | LATER (marked separately; same dispatcher, different transport) |

**Recommendation:** one command set (`src/core/api/ApiDispatcher.js`, runtime-agnostic) × two transports in v1 — the **named pipe** for live control and the **job file** for one-shot converts — both terminating in Electron main, both reusing `LaunchArgs` validation and opaque tokens. Security model shared by both: (1) paths are accepted **only in main** and only in `scene.import`, `library.mount`, `project.open`, `export.run.outDir`, `render.png.outFile`, `project.saveAs.file`; (2) every path goes through `validateLaunchPath` (realpath, device/ADS/NUL rejects, kind, size, allowlist) extended with kind `outputDir` (existing directory, writable) and `outputFile` (parent exists, extension on the export whitelist, refuses existing file unless `overwrite:true`); (3) the renderer never sees a path: imports arrive as `{ref,name}` tokens, exports return `{path, blob}` to main which writes under the validated dir with `writeDialogTarget`-style atomic write and returns absolute paths **to the caller only**; (4) destructive or outward actions (`project.open/new` on dirty, `repair.run`, `publish.*`) fail closed with `E_CONFIRM_REQUIRED` unless the request carries `confirm:true` — a hidden instance never pops a dialog; (5) limits: 1 request in flight (serial, same `isBusy` gate as LaunchRequests), 4 connections, 1 MiB per message, 32 imports / 1 GiB each, 10 min per request, events capped 50/s; (6) feature flag `settings.api.enabled` (default ON, same-user only) shown in Preferences; (7) web/OPFS: `E_UNSUPPORTED` for every path-taking method; the dispatcher exists so the postMessage transport can follow.

## 3. Scope

**v1 BUILD NOW (owner's stated use):** app.info/capabilities/ping · project.new/open/save/saveAs/info · scene.list/get/import/remove/select · scene.transform (position mm, rotation deg, scale factor) · library.mount/list · printer.list/get/set · validate.run · readiness.get · cost.quote · export.run · render.png + render.thumbnail · events (objectAdded/Removed, selectionChanged, validationDone, exportDone, projectOpened/Saved, busy) · batch `--job` · docs + ADR + error model + `apiVersion`.
**NEEDS OWNER DECISION:** repair.run via API (geometry mutation, nondeterministic engine) — recommend YES behind `confirm:true`; publish.* via API — recommend NOT in v1 (outward, paid files; v2 behind `confirm:true` + visible window + the existing final-price button text echoed in the result); API default ON vs opt-in — recommend ON (token-gated, same user); localhost HTTP bridge — recommend NO; `--hidden` by default for `--job` — recommend YES with `--quit`.
**v2:** `--rpc` stdio relay (Blender add-on seam = the 7.5 `ToolAdapter` typedef, no sidecar beyond it) · scale.printAt/convert · scene.group/parent · settings.get/set · history.* · render.turntable · library.importFromMount · publish.* (if decided) · `watchFiles` events. **v3 / LATER:** web postMessage embed, boolean/shader methods, hot folder (likely never).

## 5. Owner decisions (recommendation first; used as default until overridden)

1. **API on by default (same-user pipe + session token) vs opt-in in Preferences:** recommend ON by default with a visible Preferences toggle (`settings.api.enabled`) — the token file in the user profile already limits callers to the same Windows user.
2. **Destructive/outward methods need `confirm:true`** (project.new/open on dirty, scene.remove, repair.run): recommend YES — a hidden instance must never block on a dialog; a visible instance still shows the normal dialog when `confirm` is absent.
3. **repair.run in v1:** recommend YES behind `confirm:true`, result reports before/after counts (engine nondeterminism noted in the result).
4. **publish.* via API:** recommend NOT in v1; v2 only with `confirm:true`, visible window, and the final-price text echoed in the response.
5. **Localhost HTTP/WebSocket bridge:** recommend NO (browser-reachable surface); revisit only if a real caller cannot open a named pipe (`--rpc` stdio relay covers Blender/Python).
6. **`--job` defaults:** recommend `--hidden --quit` implied when `--result` is given and no instance is running; forwarding to a running instance keeps that window visible.
7. **Overwrite policy for export/render outputs:** recommend refuse-by-default (`E_PATH_REJECTED exists`) with explicit `overwrite:true`.
8. **Limits:** 4 clients, 1 MiB/frame, 32 imports/request, 1 GiB/file, 10 min/request, 64 steps + 20 min per job — raise on request.
9. **Web embed (postMessage):** LATER; needs an origin allowlist decision before any work.
