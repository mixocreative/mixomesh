## What was wrong, by the person it hit

**Anyone saving.** Opening project B while A was saving wrote A into B and said "Project saved" (A-08).
Edits made during a slow save were marked saved but not in the file (A-01). A save could mix live objects
with older shaders (A-02). A 5M-triangle project froze the tab and never saved (W-00; now 4.8 s). On
Safari/iPad a failed save destroyed the previous good file (B-05). Autosave could stop with no sign, and an
unreadable autosave after a crash looked like "nothing to recover" (B-02, B-03). Ctrl+S during a load saved
a half-loaded scene.

**Anyone reopening.** Textured OBJs not from a library folder lost their textures (A-09). Set scale shrank
the part 10x (W-01). A malformed or cyclic `.mixo` wiped the open scene before failing (C-07, D-04).

**Anyone printing.** Two materials named alike printed the same colour (C-03). A space in a name stripped
all OBJ colour (C-02). UV offset/scale/rotation never reached the export (C-04). Textured 3MF imports were
upside down (C-01). PrusaSlicer/Bambu cavities and modifiers imported as solid (C-05). A multi-material OBJ
was split and repaired along its colour seams (A-10).

**Anyone publishing to Cults3D.** A lost reply or a reload mid-publish created a second live listing
(F-01, B-04). "Update listing" claimed to update files Cults keeps (D-02).

**Anyone automating the desktop app.** A damaged settings file switched the turned-off API back on (B-01).
A failed API open marked unsaved work as saved (F-04). Saves, exports and repairs did not count as busy
(A-04).

**The next engineer.** One test never ran (E-01). CI deleted the lockfile and published without tests
(B-07, E-02); it now runs `npm ci`, lint, typecheck, tests and i18n:check before deploying.
